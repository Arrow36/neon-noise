# NEON//NOISE

一个直接运行在浏览器中的实时噪音频谱分析仪，用于观察环境噪音、定位稳定频率峰值，并回看最近 20 秒的频谱变化。

## 在线使用

打开 NEON//NOISE https://arrow36.github.io/neon-noise/

首次使用时，请允许浏览器访问麦克风。建议使用最新版 Chrome 或 Edge；部分内置浏览器可能不会开放麦克风接口。

## 主要功能

- 32768 点 FFT 实时频谱分析
- 1 Hz 到当前 `AudioContext` 实际采样率一半的分段对数频率坐标与峰值保持；20 Hz–20 kHz 是主显示区域
- 按真实时间戳显示的最近 20 秒历史频谱瀑布图；掉帧和后台暂停造成的缺口会留空
- 在 Web Worker 中执行平均功率、中位数、最大响声及噪声突出度分析
- 可点击、拖动或手动输入频率的自定义测量点
- ±36 dB 输入增益调节、暂停时释放麦克风与继续采集
- 针对手机和低性能设备降低绘制负载

## 本地运行

麦克风接口通常要求安全上下文。不要直接用 `file://` 打开文件，请在项目目录启动本地 HTTP 服务，例如：

```bash
python -m http.server 8000
```

然后访问 <http://localhost:8000/>。

## 使用方法

1. 点击“启动麦克风”并允许麦克风权限。
2. 在当前频谱中观察主要峰值，在历史频谱中查看它们是否持续出现。
3. 点击任一图表可创建测量点；拖动测量点可改变频率，再次点击标签可手动输入频率。
4. 点击“分析历史频谱”，从已有的最近 20 秒数据生成分析结果；不必等待满 20 秒。
5. 使用分析方式切换总体能量、稳定底噪、短促异响和持续噪声特征。
6. “暂停采集”会停止音轨并关闭 `AudioContext`，同时冻结当前历史视图；点击“继续采集”会重新请求麦克风。若新采样率与旧会话一致，暂停期间会显示为空白缺口；若采样率改变，不兼容的历史会重置。

历史分析计算及结果展示期间，增益滑块会锁定；返回实时频谱后可再次调整。改变输入增益会立即清空历史、分析结果和峰值保持。新历史会等待增益平滑稳定及完整的当前 FFT 分析窗时长，避免把旧增益或过渡状态的数据混在一起。

## 分析方式

- **平均功率频谱（总体能量）**：先在线性功率域求平均，适合观察一段时间内的总体声能。
- **中位数频谱（稳定底噪）**：降低偶发声音的影响，更适合寻找持续存在的背景噪音。
- **最大响声频谱（短促异响）**：保留每个频率在历史窗口内的最高值，突出短暂事件。
- **噪声频谱（噪声突出度＋出现率）**：综合频率相对周边的突出程度和历史出现频率，帮助寻找持续窄带噪音。

## 读数说明

- 频率单位为 Hz。
- 电平单位为 dBFS，是相对于数字满刻度的电平，并非经过声压校准的 dB SPL。
- 横轴从 1 Hz 显示到实际采样率的一半（Nyquist 频率），例如 44.1 kHz、48 kHz 和 96 kHz 采样率的上限分别为 22.05 kHz、24 kHz 和 48 kHz。上限在音频初始化后读取，不假定设备支持特定采样率。
- 横轴将 1–20 Hz 与 20 kHz 以上至实际上限各压缩为一小段，把主要空间留给 20 Hz–20 kHz。刻度文字与对应刻度线对齐；实际高频上限标在轴的右上角。
- 1 Hz 是对数横轴的显示起点，不是 1 Hz 测量精度。实际最低非零频点及频点间距为 `采样率 / 32768`；直流 0 Hz 分量被排除。界面会显示实际采样率、FFT 大小、频点间距和分析窗时长。
- 扩展显示范围不代表普通麦克风能够准确测量次声或超声。设备频响、模拟滤波和浏览器音频处理通常会限制可用带宽。
- 频谱结果会受到麦克风频响、自动增益、降噪处理、设备摆放和房间反射影响。
- 本工具适合定位和比较噪音频率，不替代经过校准的专业声级计或测量麦克风。

## 隐私

音频只在当前浏览器中通过 Web Audio API 实时处理。此项目不包含服务器端音频上传或存储功能，刷新或关闭页面后历史数据会消失。

## 技术结构

项目无运行时依赖、无需构建，可直接静态部署：

- `index.html`：界面、音频生命周期与绘图
- `spectrum-core.js`：频率映射、像素频段聚合、时间轴和可测试状态逻辑
- `analysis-worker.js`：历史频谱计算 Worker

瀑布图与当前频谱共用像素到频段的映射。每个像素列默认取其覆盖 FFT bin 的最大电平，以保留高频窄带峰；低频处一个 bin 跨越多个像素时会复用该 bin。映射会在画布尺寸、采样率、FFT 大小或频率边界变化时重建。

## 测试

测试仅使用 Node.js 内置测试运行器，不安装依赖：

```bash
npm test
```

可用 `npm run bench` 重复运行纯算法基准。基准只比较列聚合与约 182 帧历史的 `push/shift` 开销；目前后者开销很小，因此没有改用环形缓冲区。此基准不包含浏览器画布、Worker 通信或麦克风采集，不应解读为整机性能提升。

自动化测试覆盖 ±36 dB 增益约束与历史重置接线、不同采样率的频率边界和 bin 安全、20 Hz 以下与 20 kHz 以上的合成峰、高频窄带峰聚合、20 秒时间轴、Worker 分析算法、任务失效代次及初始化失败重试状态转换。

这些测试使用合成频谱和状态模型，不等同于真实麦克风实测。不同设备上的可测频带、底噪、系统自动处理和恢复行为仍需在目标浏览器与硬件上验证。
